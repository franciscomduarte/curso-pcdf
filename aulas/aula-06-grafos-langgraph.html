Aula 6 · Modelagem de Sistemas Baseados em Grafos

O fluxo vira um grafo que dá para desenhar

Na Aula 5, os cinco padrões eram cinco arquivos com for, while e if escondendo o fluxo. Esta aula transforma o fluxo num objeto explícito: nós, arestas, estado compartilhado, condicionais e um ciclo — o modelo que o LangGraph formaliza.

Bloco 1 · Abertura e contextualização · 25 min

O problema: o fluxo está escondido no código

Pegue o Supervisor da Aula 5: um while, um llm.decidir(), um if proximo == "concluir". Para responder "o que acontece depois de classificar?" você precisa ler o loop. Para testar um caminho específico, precisa montar o estado certo e torcer. Para mudar a ordem, mexe na lógica de controle.

Um grafo de execução tira o fluxo de dentro do código de controle e o coloca num objeto: os nós (as etapas) e as arestas (as transições possíveis). Aí dá para desenhar o fluxo, validar antes de rodar, instrumentar cada caminho, e mudar a rota sem tocar nas etapas. É o que o LangGraph faz — e hoje construímos a versão mínima para entender o mecanismo.

Bloco 2 · Fundamentos teóricos · 50 min

Grafo: nós e arestas

Um grafo dirigido é um conjunto de nós ligados por arestas com direção (setas). Aqui: cada nó é uma etapa — uma função no(estado) → estado; cada aresta é uma transição possível. Dois nós sentinela, START e END, marcam começo e fim.

flowchart LR I(("START")) --> A["nó A"] --> B["nó B"] --> F(("END"))

O grafo mais simples: uma sequência. A execução entra por START, roda cada nó, segue a aresta, e para em END.

Estado compartilhado

Um único objeto — o Estado — passa por todos os nós. Cada nó lê o que precisa e escreve a sua contribuição. É o Dossiê da Aula 5, com dois campos a mais para o grafo se enxergar: caminho (a sequência de nós visitados) e passos (a trava da Aula 4).

DAG × ciclo

flowchart LR subgraph DAG["DAG — grafo acíclico dirigido"] a1["A"] --> a2["B"] --> a3["C"] --> a4(("END")) end subgraph CIC["Grafo com ciclo"] b1["A"] --> b2["B"] b2 -- "condição de saída falsa" --> b1 b2 -- "verdadeira" --> b3(("END")) end

Num DAG (sem volta) a execução sempre termina — não há como voltar. Um ciclo (uma aresta que retorna a um nó já visitado) só é seguro se o roteador tiver uma condição que eventualmente fica falsa — e mesmo assim precisa da trava de passos como rede.

Aresta condicional — o roteador

Uma aresta estática sempre vai para o mesmo destino. Uma aresta condicional tem um roteador: uma função rota(estado) → nome_do_próximo_nó que decide para onde ir a partir do estado atual.

flowchart LR C["classificar"] --> R{"roteador — o estado diz o quê?"} R -- "relato confuso" --> H["encaminhar_humano"] R -- "senão" --> N["consultar"]

O roteador roda depois do nó classificar — ele enxerga o estado já atualizado. É assim que o fluxo se adapta ao caso.

Os padrões da Aula 5, agora como grafos

flowchart LR subgraph PIPE["Pipeline = arestas estáticas em linha"] p1["extrair"] --> p2["classificar"] --> p3["consultar"] --> p4["revisar"] end subgraph SUP["Supervisor = estrela + ciclo condicional"] s0{"supervisor"} --> s1["extrair"] s0 --> s2["classificar"] s0 --> s3["..."] s1 --> s0 s2 --> s0 s3 --> s0 end

Pipeline é uma linha de arestas estáticas. Supervisor é uma estrela: cada especialista volta ao supervisor, que decide o próximo por uma aresta condicional. Blackboard é mais difícil de desenhar como grafo fixo — as arestas mudam com as dependências.

LangGraph

O LangGraph (LangChain) é a biblioteca que formaliza isso. Você declara um StateGraph, adiciona nós e arestas, compile(), e invoke(estado). O que ele acrescenta ao motor mínimo:

Motor mínimo (nosso)LangGraph
o nó devolve o estado inteiroo nó devolve só as chaves que mudou; o LangGraph faz o merge
caminho acumulado à mãoAnnotated[list, reducer] — o reducer concatena
roteador devolve o nome do nóroteador devolve um rótulo; um dicionário mapeia rótulo → nó
max_passos no compilarrecursion_limit no invoke
execução estritamente sequencialramos independentes em paralelo; checkpointing; pausa para humano (Aula 7); streaming

Leitura de referência — reducer, recursion_limit e checkpointing (últimas 3 linhas da tabela) não precisam de tempo ao vivo aqui: voltam como prévia da Aula 7, onde checkpointing e pausa para humano são o assunto central.

Grafos e DAGs: Cormen et al., Introduction to Algorithms, cap. 22. LangGraph: documentação oficial. Modelo "pense como um vértice": Pregel (Malewicz et al., 2010). Ver Referências.

Peça 2 — o grafo (nós, arestas, validação)

app/grafo.py — trechos
START, END = "__start__", "__end__"

class Grafo:
    def no(self, nome, funcao):           # registra uma etapa
        self._nos[nome] = funcao; return self

    def aresta(self, origem, destino):     # transição fixa
        if origem == START: self._entrada = destino
        else: self._arestas[origem] = destino
        return self

    def aresta_condicional(self, origem, roteador):   # roteador(estado) -> nome do nó | END
        self._condicionais[origem] = roteador; return self

    def validar(self):
        if self._entrada is None: raise GrafoInvalido("falta aresta de START")
        for nome in self._nos:
            if nome not in self._arestas and nome not in self._condicionais:
                raise GrafoInvalido(f"nó '{nome}' não tem aresta de saída")
        # ... e toda aresta aponta para nó existente

    def compilar(self, max_passos=25):
        self.validar()
        return GrafoCompilado(self, max_passos)
app/grafo.py — o laço de execução
def executar(self, estado):
    atual = self._g._entrada
    while atual != END:
        if estado.passos >= self._max:                  # a trava da Aula 4
            estado.pendencias.append(f"grafo interrompido: {self._max} passos")
            return estado
        estado.visitou(atual)
        estado = self._g._nos[atual](estado)            # roda o nó
        if atual in self._g._condicionais:
            atual = self._g._condicionais[atual](estado)  # roteador decide
        else:
            atual = self._g._arestas[atual]               # aresta fixa
    estado.caminho.append(END)
    return estado

Bloco 7 · Debriefing · 15 min

Trade-offs e riscos

  • Grafo × código de controle. Fluxo simples e fixo (2–3 passos) → um if resolve. Fluxo com ramos, ciclos, e que muda com frequência → grafo: dá para desenhar, validar e instrumentar. O grafo tem mais cerimônia.
  • DAG × ciclo. Prefira DAG sempre que possível — terminação garantida. Só use ciclo quando a tarefa realmente é "tente, avalie, tente de novo" — e sempre com condição de saída e trava.
  • Motor próprio × LangGraph. Para entender e para casos pequenos, o motor de 80 linhas basta. LangGraph vale quando você precisa de paralelismo real, checkpointing (retomar de onde parou) ou pausa para humano.

Segurança

⛔ Ciclo runaway

Um roteador com condição de saída que nunca fica falsa transforma o grafo num gerador de custo (o mesmo LLM10 / consumo ilimitado da Aula 4). A trava de passos tem que estar lá, e passos altos demais escondem o problema.

⛔ Roteador lê dado não confiável

Se a rota depende de um campo que veio do texto da ocorrência (confuso, tem_violencia), um relato pode se "auto-rotear" para o caminho rápido. Valide o campo; ou faça o roteamento depender de sinais que o agente não controla.

⛔ Estado compartilhado mutável

Dois nós que escrevem o mesmo campo criam ordem-dependência silenciosa. O LangGraph usa reducers explícitos; no motor mínimo, a ordem é sua responsabilidade — documente quem escreve o quê.

  • Observabilidade de graça. O caminho de cada execução responde "por que esta ocorrência foi para este ramo" — registre-o.
  • Protótipo ≠ produção. Falta: execução paralela real, retomada após falha (checkpoint), versionamento do grafo (Aula 9).
⚠️ Ponto de atenção — uso responsável

O grafo é a rota, não o veredito. Que uma ocorrência passe por consultar duas vezes ou desvie para encaminhar_humano é uma decisão de processo — registrada no caminho e auditável. Repare que um relato confuso ou com dados faltando vai para o humano por desenho do grafo, não por acaso: o sistema é construído para devolver ao servidor o que não consegue tratar com segurança. Nenhum nó tipifica um crime ou aponta autor — isso continua fora do grafo.

Lab intermediário — ramos + junção

lab_intermediario(): veiculo → historico → juntar. No motor mínimo os ramos são sequenciais porque o laço de execução segue uma aresta por vez — não há fila de nós ativos. O LangGraph mantém um "super-step" com todos os nós prontos e os roda em paralelo; a junção espera todos. Desafio — Supervisor como grafo

esboço
g.no("supervisor", no_supervisor)     # chama llm.decidir(e), guarda a escolha em e
for nome in ("extrair", "classificar", "consultar", "revisar"):
    g.no(nome, REGISTRO[nome])
    g.aresta(nome, "supervisor")       # cada especialista volta ao supervisor
g.aresta(START, "supervisor")
g.aresta_condicional("supervisor", lambda e: e.escolha)   # "extrair" | ... | END

A trava de passos do GrafoCompilado substitui o max_rodadas da Aula 5. O grafo tem 5 nós e ~9 arestas contra um while de 8 linhas — mas o fluxo está no desenho, não na cabeça de quem leu o código. Onde parar para o humano: um nó aprovar_humano entre revisar e END, que no LangGraph usa interrupt() + checkpoint — a Aula 7.

Avaliação — respostas-guia

  1. Nó = uma função-etapa sobre o estado; aresta = uma transição possível entre nós.
  2. DAG não tem como voltar → o número de transições é limitado. Ciclo pode revisitar um nó indefinidamente se a condição de saída nunca ficar falsa.
  3. Estática = destino fixo; condicional = um roteador decide. O roteador roda depois do nó de origem, com o estado já atualizado.
  4. tem_ciclo() só olha arestas estáticas; o ciclo revisar → consultar é uma aresta condicional — depende do estado, então não é analisável só pela topologia.
  5. Ex.: execução paralela de ramos; checkpointing / retomada; pausa para humano; merge por reducer; streaming.

Desafio (roteador): não é detectável estaticamente porque o roteador é código arbitrário — pode devolver qualquer string. Mitigação: o GrafoCompilado.executar valida o retorno do roteador em runtime (if prox not in self._g._nos and prox != END: raise) e falha com mensagem clara em vez de KeyError. É o que o LangGraph faz ao exigir o dicionário {rótulo: nó}.

Evolução do SIGMA — Aula 6

O fluxo do SIGMA agora é um grafo explícito: dá para desenhá-lo, validá-lo antes de rodar, e ver o caminho de cada ocorrência. Na Aula 7, os nós deste grafo viram agentes com papéis (Investigador, Jurídico, Analista) — cada um com o seu loop e a sua memória — e alguns nós passam a parar e esperar a aprovação de um humano antes de continuar. Para isso o grafo precisa persistir o estado (checkpoint) e saber retomar.

flowchart LR O[("Boletim sintético")] --> G{{"grafo de execução do SIGMA"}} G --> H["Revisão humana"] G -. "caminho + passos" .-> AU["Auditor"] G -. "Aula 7: nós que pausam para aprovação" .-> HITL["Human-in-the-loop"]

O que a Aula 6 acrescentou: o fluxo virou um grafo com nós, arestas condicionais e um ciclo controlado — e cada execução registra o caminho percorrido para o Auditor.

"Enquanto o fluxo está num while, só quem leu o código sabe o que o sistema faz. Quando o fluxo é um grafo, dá para desenhá-lo numa reunião — e discordar dele."
